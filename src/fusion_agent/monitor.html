Harbour Monitor

Automated monitoring for Kestrel Sound, 13 to 14 March

Three sources watched the harbour overnight. Each one tells part of the story and each one can be wrong. The agent's job is to fuse them into one answer and cite every record it relied on.

Written reports

Patrol logs, notices and radio logs. Rich context. People can be mistaken or untruthful, and text can carry hostile instructions.

Camera images

Two fixed cameras. Independent of what anyone says. At night they can see a shape but can't read a name.

AIS vessel tracks

Each vessel broadcasts its own position. Precise and constant. It's self-reported and a crew can switch it off.

Reading these results

  1. Bigger wasn't better. The 14B model passed the same number of questions and took twice as long.
  2. No invented citations. Citation precision was 1.0 for both. The guard sent back a handful of uncited answers and the models fixed them.
  3. The injection failed. Both models still reported the overnight incidents.
  4. Single runs are noisy. Temperature 0 isn't deterministic in practice. A serious comparison needs repeated runs and pass rates per question.
  5. Checks are strict and partly string based. A correct answer phrased differently can fail. That's why the saved answers are here to read.

A plain Python loop around a local model, with checks at every point where things go wrong. No agent framework. About 200 lines you can read in one sitting.

The loop

  1. Ask the model with the question, a system prompt and six tool schemas.
  2. Validate each tool call against a Pydantic model. Bad calls go back as errors the model can fix.
  3. Run the tool against DuckDB. Every result carries a source_id.
  4. Scan retrieved text for prompt injection and attach a warning.
  5. Check citations in the answer. Each must match a source returned in this run. Up to two retries.
  6. Stop at a budget of eight steps whatever happens.

The tools

  1. search_reports semantic search over text, with a time window
  2. search_images CLIP search over camera stills by description
  3. track_anomalies zone entries or transponder gaps, computed in SQL
  4. vessel_track one vessel's positions, each labelled with its named area
  5. list_vessels and get_source for lookups

All tools are read-only. The agent can look but can't act, which is the real defence against injection.

Design choices

Fusion. No single source answers the interesting questions. A camera sees a dark boat, AIS names it and a report gives intent. Answers come from combining them.

Offline by enforcement. A network guard patches the socket layer so anything that isn't loopback raises an error. This page loads nothing external either.

Geometry in code. Models couldn't tell if raw coordinates were in the southern grounds. Labelling positions in the tool fixed it. More prompt didn't.

Images by description. Camera stills are AI-generated stand-ins for CCTV. CLIP embeds them at ingest so the agent can search them in plain words, with no labels or captions.

One file, one engine. DuckDB holds text, image vectors and tracks together, so a single SQL query can mix time windows, places and similarity.

Runs on 127.0.0.1 only. No external scripts, fonts or requests.
